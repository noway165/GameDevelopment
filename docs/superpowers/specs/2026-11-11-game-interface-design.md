# Project METROPOLIS: Game Interface and Windows Build Design

**Date:** 2026-11-11
**Status:** Implemented
**Source:** Project METROPOLIS Game Development Blueprint v1.0
**Builds on:** `2026-11-09-simulation-core-design.md`, `2026-11-10-unity-world-construction-design.md`

## 1. Intent

This is the first half of sub-project 3. It turns the playable prototype into a complete
game loop that runs outside the Editor.

**Success:** double-clicking `Metropolis.exe` opens a menu. The player starts or
continues a city, plays with mouse-driven tools and a readable HUD, saves, quits, and
continues later from the same state.

Everything in the scene is still generated by `WorldBuilder`, because the developer is
new to Unity. No hand work in the Editor is required.

## 2. Scope

**In scope:** main menu, pause menu, HUD, toolbar, information line, tax control, save
and load with one slot, new-city flow, pointer blocking over UI, Windows build script,
removal of the debug readout.

**Deferred to the second half of sub-project 3:** information overlays, final art,
audio, player settings, multiple save slots.

**Decided by the developer:** a city that has run out of money is not rescued by a rule
change. The player starts a new city from the menu, and the HUD warns when the budget is
negative.

## 3. Screens

All UI text is English.

**Main menu**, shown on launch over the world: `Continue` (only when a save file
exists), `New City`, `Quit`. It is an overlay in `GameWorld`, not a separate scene.

**Top bar:** day, population, budget, last day's net income, power left, water left,
residential, commercial and industrial demand, speed buttons (pause, 1x, 2x, 4x), tax
rate with `-` and `+`, and a `Menu` button. A negative budget is shown in red with the
text `City is in debt`.

**Toolbar**, at the bottom: Road, Bulldoze, Residential, Commercial, Industrial, Power
Plant, Water Pump. Each button shows its hotkey and cost. The active tool is highlighted.

**Information line**, above the toolbar: the last refusal in plain words, and for the
building under the pointer, its name and why it is not running.

**Pause menu**, opened by `Menu` or by Esc when no tool is selected: `Resume`, `Save`,
`New City`, `Quit`. The simulation is paused while any menu is open and returns to its
previous speed on resume.

**Dialogs:** a confirmation before `New City` from the pause menu, and an error dialog
listing problems when a save cannot be read or written.

## 4. Session rules

- On launch a fresh city exists behind the main menu, and no session is active.
- `New City` or a successful `Continue` starts a session.
- Saving is possible only during a session, so quitting from the main menu never
  overwrites a save with an empty city.
- `Save` and F5 write the save and confirm on the information line.
- `Quit` from the pause menu saves first. If saving fails, the error is shown and the
  game does not quit.
- `New City` does not delete the save file. The next save replaces it.
- Closing the window by other means does not save.

## 5. Save and load

- One file: `Application.persistentDataPath/city.json`, written through the core's
  `SaveSerializer` and `SaveFile`, which keep a `.bak` copy.
- `Continue` loads it through `SaveSerializer.TryLoad`. On failure the error dialog lists
  the problems, the file is left untouched, and the main menu stays open.
- After a load, every view is rebuilt from the loaded city and the HUD shows current
  values at once.

## 6. Input rules

- A pointer over any UI element never reaches the world: no hover preview, no click.
- While a menu or dialog is open, game hotkeys and camera input are ignored.
- Existing hotkeys keep working. New: F5 saves, Esc with no tool opens the pause menu.
- Losing application focus cancels an active drag.
- Tax changes go through `SetTaxRateCommand`, one point per click, within
  `0..MaxTaxRate`.

## 7. Components

| Unit | Responsibility |
|---|---|
| `SaveService` | Plain class around one save path: `Exists`, `TrySave`, `TryLoad`. |
| `HudText` | Plain static class. Formats numbers and turns `CommandFailure` and `BuildingStatus` into sentences. |
| `GameController` | Gains `StartNewCity()`, `TryContinue(out errors)`, `TrySave(out error)`, `SessionActive`, and rebuilds simulation, tools and views when the city changes. |
| Views | Gain `Dispose()`, which unsubscribes from events and destroys their objects. |
| `GameUi` | MonoBehaviour on a `UIDocument`. Builds the whole interface in code and styles it with one USS file. Refreshes labels from state every frame, setting text only when it changed. |
| `InputBridge` | Applies the rules in section 6. |
| `WorldBuilder` | Also generates `PanelSettings`, a theme file importing Unity's default runtime theme, the `UIDocument` and `GameUi`. Removes `DebugReadout`. |
| `BuildScript` | Editor method that builds `Builds/Windows/Metropolis.exe` for Windows 64-bit with the Mono backend. |

The UI reads the simulation and calls `ToolController`, `SimulationClock`,
`GameController` and commands. It holds no game rules.

## 8. Core changes

- `Simulation.RefreshDerived()` also fills housing, unemployment, attractiveness, revenue
  and expenses without changing population or budget, so the HUD is correct after a load
  and before the first day. This closes a deferred finding from sub-project 1.
- No rule or formula changes.

## 9. Error handling

- A missing or unreadable save never crashes and never deletes data.
- A failed save reports the reason and leaves the previous file and its `.bak` intact.
- `StartupCheck` also reports a missing `UIDocument` or `PanelSettings`.
- If the UI cannot be built, the game logs one error and stays playable by hotkey.

## 10. Testing

| Layer | Covers | Runner |
|---|---|---|
| Core | `RefreshDerived` fills statistics without changing saved JSON | `dotnet test` |
| EditMode | `HudText` formats and messages for every `CommandFailure` and status flag, `SaveService` round trip, missing file, corrupt file, scene wiring | Unity |
| PlayMode | New city, build, save, new city, continue restores the saved city and its view counts. Menus pause the clock. A pointer over UI does not build. Save is refused with no session. | Unity |
| Built player | `Metropolis.exe` launches, runs for 20 seconds and exits with no exception in its log | Script |
| Playtest | Menus, buttons, readability, save and continue across a restart, from a short checklist | Developer |

## 11. Definition of done

- All automated tests pass, including the existing 136 core, 178 EditMode and 7 PlayMode
  tests.
- `Builds/Windows/Metropolis.exe` is produced by one command and passes the launch check.
- MVP acceptance criteria 1, 9 and 10 are met in the built game: create a city, pause and
  accelerate, save and load.
- The developer's playtest of the built game passes.

**Not verifiable by code alone:** how the interface looks and reads. The developer's
playtest covers it.
